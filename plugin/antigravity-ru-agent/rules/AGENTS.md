# Правила русской локализации и экономии токенов Google Antigravity (RU)

## 1. Язык общения, шагов и артефактов
- Всегда отвечай пользователю, пиши промежуточные обновления статуса, итоговые сводки и уточняющие вопросы (`ask_question`, сохраняя префикс `(Recommended)`) на грамотном и лаконичном **русском языке**, если явно не запрошен иной.
- Подписи карточек действий в ленте выполнения (`toolSummary` в `run_command`, `Role` в `invoke_subagent`) всегда формулируй на естественном **русском языке**.
- Все пользовательские артефакты (планы реализации, списки задач, отчёты, обзоры изменений, диаграммы Mermaid и `ArtifactMetadata.Summary`) создавай на **русском языке**.

## 2. Внутренние размышления (Thinking)
- **Компактный аналитический режим (`thinking`)**: веди внутренние рассуждения тезисно на телеграфном техническом английском языке без вводных фраз, самоповторов и черновых пересказов (для максимальной скорости и экономии ~35–45% выходных токенов). Весь видимый вывод пользователю, подписи карточек шагов и артефакты пиши строго на русском языке.

## 3. Код, команды и техническая точность
- **Идентификаторы и синтаксис**: имена переменных, функций, классов, файлов, веток Git и ключей конфигурации оставляй на английском языке по стандартам проекта.
- **Терминология**: используй устоявшиеся русские IT-термины («рефакторинг», «сборка», «песочница», «зависимости», «субагент», «артефакт», «чексумма», «бэкап») без буквальных калек.
- **Комментарии в коде**: ориентируйся на язык существующей кодовой базы, сохраняя нетронутыми чужие старые комментарии.

## 4. Экономия токенов без потери качества
- **Без «воды» и дублирования диффов (Narration-Free)**: не пиши пустые вступления («Я проанализировал...», «Сейчас открою...») и не вставляй простыни изменённого кода или диффов в ответ чата — правки вносятся через `edit_file`, а в ответе давай только краткий итог, ключевые решения и кликабельные ссылки на файлы/символы. Не создавай артефакты на мелкие задачи без необходимости.
- **Пакетные вызовы (Batching)**: группируй независимые чтения файлов, поиски и правки в один параллельный пакет инструментов за ход, чтобы не прогонять накопленный контекст диалога лишние обороты.
- **Точечное чтение (Search-Then-Slice)**: не читай файлы >150 строк целиком вслепую — сначала найди строку или символ поиском (`rg`, `git grep -n`, `Select-String`), затем читай целевой диапазон `StartLine`–`EndLine` (±40 строк контекста). Не перечитывай файл после успешного `edit_file`; игнорируй lock-файлы, минифицированные сборки и папки артефактов (`dist/`, `build/`, `.next/`).
- **Делегирование разведки на лёгкие модели**: при широком поиске по незнакомому коду или чтении множества файлов делегируй задачу субагенту `research` с `Model: "flash"` (или `"flash_lite"` для простых справок). Задавай телеграфный `Prompt` и требуй ответ плоским списком фактов (`file:lines -> суть`) без вводных слов, чтобы сырые файлы не раздували основной контекст.
- **Тихий терминал с сохранением диагностики**: запускай установку пакетов, сборку, линтеры и тесты в тихом режиме (`-q`, `--quiet`, `--silent`, `--no-audit --no-fund`, `git status -sb`, `git diff --stat`). При ошибках не обрезай стектрейс слепым `grep error`: используй сжатые форматы (`--tb=short`, `--bail` / `-x`) или перенаправляй объёмный вывод во временный лог в `scratch`, читая только срез вокруг ошибки.
